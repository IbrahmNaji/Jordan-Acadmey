# منصة الأكاديمية وإدارة العملاء

هذا المستودع يضم تطبيق ويب React/Vite وخادماً Express/Prisma لإدارة العملاء والأكاديمية.

## الحالة الحالية

- الموقع العام ولوحة CRM موجودان.
- إدارة الدورات والدفعات والمدربين والحضور مرتبطة بقاعدة البيانات.
- إعلانات المركبات تتطلب تفويض المالك وموافقة إدارية قبل النشر. لا تعرض الواجهة العامة بيانات المالك أو ادعاء فحص غير موثق.
- صفقات الوساطة مستقلة عن تسجيلات الأكاديمية، مع سجل مراحل ومعاينات واتفاقات عمولة ودفعات منفصلة.
- نماذج طلب موعد الورشة وطلب قطع الغيار تحفظ الطلبات والموافقة على الخصوصية. لوحة `/admin/operations` تتيح المراجعة، أوامر العمل، التسجيل اليدوي لنتائج الفحص، الموافقة الموثقة، الفواتير والمدفوعات، وعروض قطع الغيار متعددة الموردين.
- ترحيلات المركبات والوساطة والورشة وقطع الغيار اختُبرت على قاعدة منفصلة، ثم طُبقت على قاعدة التطوير بعد إنشاء نسخة احتياطية PostgreSQL والتحقق من أرشيفها. لم تُجر استعادة فعلية للنسخة الاحتياطية.
- المتبقي من البرومبت: سجل تغييرات موحد لبعض وحدات الورشة والقطع، صفحات تقارير مالية مستقلة لكل نشاط، خدمة صور/مرفقات خاصة، جدولة وتذكيرات خارجية، فهرسة إعلانات منتهية وتجديدها، تهيئة كتالوج خدمات ومراحل مرنة، واختبارات متصفح E2E. هذه المنظومة ليست مكتملة للإنتاج بعد.
- اختبار الدخان يتطلب قاعدة محلية منفصلة اسمها ينتهي بـ`_test` أو `_smoke`، ويرفض استخدام `DATABASE_URL` مباشرة.

## المتطلبات

Node.js وإصدار npm المتوافقان مع إصدارات Vite وPrisma المقفلة في ملفات الحزم، وخادم PostgreSQL متاح. لا تُستخدم بيانات اعتماد افتراضية في الإنتاج.

## الإعداد المحلي

1. انسخ `server/.env.example` إلى `server/.env`، واضبط `DATABASE_URL` وأسرار JWT وعنوان العميل وإعدادات المشرف وفق بيئة التطوير.
2. انسخ `client/.env.example` إلى `client/.env`، واضبط عنوان API وبيانات الاتصال المركزية. استخدم نطاق HTTPS الحقيقي في `VITE_SITE_URL` قبل بناء نسخة الإنتاج.
3. ثبّت الحزم في كل تطبيق باستخدام `npm ci` داخل مجلدي `server` و`client`.
4. في قاعدة تطوير فارغة أو مخصصة للاختبارات فقط، نفّذ `npm run db:generate` ثم `npm run db:migrate` داخل `server`.
5. شغّل الخادم بـ`npm run dev` داخل `server` والواجهة بـ`npm run dev` داخل `client`.

لا تنسخ ملف `.env` من جهاز آخر ولا تضف أسراراً إلى Git.

## البناء والفحوصات

- الخادم: `npm run build` داخل `server`.
- الواجهة: `npm run build` داخل `client`. ينتج ملفات `robots.txt` و`sitemap.xml` إذا ضُبط `VITE_SITE_URL`.
- التدقيق: `npm run lint` داخل `client`.
- اختبار التكامل: `npm run smoke` داخل `server` بعد إعداد قاعدة اختبار منفصلة باسم ينتهي بـ`_test` أو `_smoke` في `SMOKE_DATABASE_URL`.

اختبار الدخان ينشئ بيانات مؤقتة ويحذفها، لذلك لا توجّهه إلى قاعدة إنتاج أو قاعدة تحتوي سجلات فعلية.

## وساطة المركبات (Phase 4)

يوفر الخادم مسارات إدارة الإعلانات تحت `/api/vehicles` ومسارات الموقع العام تحت `/api/public/vehicles`. ترتبط المركبة بعميل/مالك موجود، وتتطلب بيانات توثيق التفويض. يبدأ الإعلان كمسودة، ثم يمر بالمراجعة؛ لا يعيد الموقع العام إلا الإعلانات المعتمدة. صلاحية الموظف محدودة بإعلاناته المسندة، ولا يمكنه الاعتماد.

تُحفظ مراجع صور الإعلانات فقط تحت `uploads/vehicles/`؛ لا توجد خدمة رفع ملفات. لا تعرض مستندات التفويض للعامة. تقدم الصفحات العامة طلب موعد ورشة وطلب قطعة غيار؛ الإرسال لا يؤكد الموعد أو التوفر أو السعر. لوحة التشغيل متاحة للمدير والمدير العام فقط.

## نشر الإنتاج

راجع تعليمات [الخادم](server/README.md) و[الواجهة](client/README.md). قبل كل ترحيل قاعدة بيانات، خذ نسخة احتياطية قابلة للاستعادة وتحقق من أرشيفها. استخدم `prisma migrate deploy` للنشر، ولا تستخدم `prisma migrate dev` على قاعدة الإنتاج. لا تنفّذ أوامر إعادة ضبط قاعدة البيانات على بيانات فعلية.

لا يطبّق هذا المشروع حالياً SSR أو prerendering. ملفات SEO الثابتة لا تحتوي روابط صفحات الدورات الفردية الديناميكية.
