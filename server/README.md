# خادم API وقاعدة البيانات

## الإعداد المحلي

انسخ `.env.example` إلى `.env` واضبط قاعدة PostgreSQL المحلية، وعناوين العميل، وسري JWT، وحساب المشرف الأول عند الحاجة. لا تحفظ القيم الحقيقية في Git ولا تسجلها في مخرجات الطرفية.

ثبّت الحزم باستخدام `npm ci`، ثم نفّذ `npm run db:generate`. لتشغيل المشروع محلياً استخدم `npm run dev`.

## ترحيلات قاعدة البيانات بأمان

قبل أي تغيير على المخطط أو تطبيق ترحيل على قاعدة تحتوي بيانات:

1. راجع `prisma/schema.prisma` وسجل `prisma/migrations`، وتحقق من قاعدة الاتصال دون طباعة سلسلة الاتصال.
2. استخدم بيانات اعتماد PostgreSQL من ملف خدمة أو `.pgpass` محلي محمي، لا من أمر مكشوف في سجل الطرفية.
3. أنشئ نسخة مخصصة بصيغة PostgreSQL، واحفظها خارج مجلد المصدر أو في مجلد النسخ الاحتياطية المستثنى من Git:

   ```powershell
   pg_dump --format=custom --file="<مسار-محمي>\academy-crm.dump" --dbname="$env:PGDATABASE"
   ```

4. تحقق من الأرشيف باستخدام `pg_restore --list "<مسار-محمي>\academy-crm.dump"`، واختبر الاستعادة إلى قاعدة منفصلة قبل اعتماد النسخة كقابلة للاستعادة.
5. اختبر الترحيل على قاعدة تطوير مستقلة. استخدم `npm run db:migrate` للتطوير فقط. في النشر، وبعد مراجعة النسخة الاحتياطية وخطة الاستعادة، استخدم `npx prisma migrate deploy`.

لا تستخدم `prisma migrate reset` أو `db push --force-reset` على قاعدة ذات بيانات. لا تحذف سجلات لتجاوز فشل ترحيل.

## اختبارات التكامل

`npm run smoke` يبني الخادم ثم ينشئ بيانات مؤقتة ويمسحها. يتطلب `SMOKE_DATABASE_URL` منفصلاً عن `DATABASE_URL`، ويشترط أن ينتهي اسم قاعدة الاختبار بـ`_test` أو`_smoke`. يستخدمه الاختبار فقط؛ لا توجّهه إلى الإنتاج أو إلى قاعدة تحتوي بيانات فعلية. عند تعذر قاعدة PostgreSQL، لا ينفذ الاختبار.

## الإنتاج

- ضبط `NODE_ENV=production` وأسرار JWT قوية وفريدة وعنوان `CLIENT_URL` المسموح.
- إنشاء قاعدة إنتاج ونسخ احتياطية دورية واختبار الاستعادة.
- تشغيل `npm run build` ثم `npm start`.
- تطبيق الترحيلات المعتمدة باستخدام `npx prisma migrate deploy` بعد النسخ الاحتياطي.
- ضبط إعداد مشرف أول بكلمة مرور قوية وفق `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD`، ثم تدوير بيانات الاعتماد حسب سياسة التشغيل.
- اتصالات البريد والرسائل الخارجية غير مُفعّلة ما لم يُضف مزود فعلي وإعداداته؛ لا يدّعي التطبيق نجاح إرسال خارجي.

الترحيلات `20261027160000_vehicle_brokerage_marketplace` و`20261027170000_brokerage_deals_commissions` و`20261027180000_workshop_and_parts_requests` مطبقة على قاعدة التطوير، واختُبرت من قاعدة فارغة ثم عبر اختبار الدخان. نسخة ما قبل الترحيل موجودة في `backups/academy-crm-before-phase5-20261027.dump` (مستثناة من Git)، وتحققنا من فهرس الأرشيف؛ لم تُختبر استعادتها فعلياً.

تتوفر إعلانات المركبات، ومسار الصفقات والعمولات تحت `/api/brokerage`، وإدارة طلبات الورشة وأوامر العمل تحت `/api/workshop`، وإدارة عروض القطع تحت `/api/parts`. الطلبات العامة تحفظ العميل وموافقة الخصوصية، مع إشعار داخلي للمديرين. لا توجد خدمة بريد أو SMS أو WhatsApp متصلة؛ الإشعارات الحالية داخل التطبيق.

الضوابط الحالية تمنع وضع إعلان على أنه مفحوص من خلال خانة إدارية؛ واجهة السوق لا تعرض ادعاء تحقق، ولا يمكن تحديده إلا لاحقاً عند ربطه بسجل فحص فعلي. إدخال نتائج الورشة يدوي ويتطلب تسجيل من أدخلها. تبقى لوحات التقارير المالية التفصيلية حسب النشاط، تعديل/تسوية الفواتير، رفع المرفقات وحمايتها، جدولة الفنيين والمواعيد، وتجديد الإعلانات منتهية، وتغطية E2E غير مكتملة.
